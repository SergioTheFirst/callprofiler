# 1. РЕЖИМ: исследовательская группа + Workflow + loop

Ты — руководитель междисциплинарной исследовательской группы, а не code-review agent.

Механика Claude Code, которую ОБЯЗАН использовать:
- `Workflow` (ultracode) — все фазы. Паттерны: multi-modal sweep (литература по разным модальностям
  поиска), loop-until-dry (пока 2 раунда подряд не дают НОВЫХ валидированных находок),
  adversarial verify (≥3 независимых опровергателя на каждое ключевое утверждение — разные
  линзы: методология / статистика / применимость к русской телефонной речи), judge panel для
  вариантов итоговой конструкции, completeness critic в конце каждого раунда.
- `/loop` (dynamic) — после каждого раунда сам планируешь следующий, пока не выполнены критерии
  остановки (§9). Не останавливайся, потому что «сделано достаточно»: критерий — §9.
- Скиллы: `superpowers:brainstorming` (§3), `deep-research` (§4), `grill-me` на итоговый план (§8),
  `superpowers:verification-before-completion` перед финалом, `planning-with-files`: ВСЁ
  промежуточное — в файлы `docs/research/bs/` после КАЖДОГО раунда (компакция контекста
  не должна терять результаты). Файлы — единственная память исследования.
- Веб: `WebSearch`/`WebFetch`/`ctx_fetch_and_index` — ТОЛЬКО для литературы, обобщёнными
  запросами. Ни одного фрагмента транскрипта, имени, номера, аудио — наружу. Никогда.
- Локальный LLM (`http://127.0.0.1:8080`) — для разметки выборок (weak supervision), извлечения
  claims, парафраз-контроля. Через `requests`, свой кэш в исследовательской БД (не `llm_calls`).
- Локальные вычисления: Python/numpy/sqlite3/librosa над исследовательской копией БД и аудио.
- Субагенты/треки создаются ТОЛЬКО под самостоятельный вопрос с сравнимым результатом.
  Каждый трек возвращает: вопрос → метод → находки с n/эффектом/CI → уровень доказанности →
  что опровергатели не смогли опровергнуть → что осталось неизвестным.

Токены: бюджет директивы `+NNNNk` — расходовать ПОЛНОСТЬЮ и осмысленно: на ширину источников,
на опровергателей, на эксперименты над данными, на повторные раунды. Не на перечитывание,
не на пересказ, не на декор.

# 2. FIRST PRINCIPLES (до литературы и до данных)

Декомпозиция: феномен → механизм → наблюдаемое проявление в ТЕЛЕФОННОЙ РУССКОЙ речи → измеримый
сигнал при ASR-шуме и хрупкой диаризации → альтернативные объяснения → статистическая устойчивость
на уровне человека → практическая ценность для владельца.

Обязательно разграничить (и для каждого — что система в принципе способна отличить, а что нет):
bullshit (безразличие к истине, Frankfurt) · ложь · ошибка · незнание · добросовестное заблуждение
· уверенность без основания · гипербола · шутка/ирония · риторическое преувеличение · самопрезентация
· манипуляция · ошибка памяти · смена позиции после новой информации · уклончивость как вежливость
(русская телефонная прагматика) · ASR-артефакт, выглядящий как противоречие.

Запрещённые подмены без доказательств: неточность→bullshit, уверенность→ложь,
противоречие→обман, эмоция→ненадёжность, короткие ответы→уклончивость.

Записать в `20-first-principles.md` ДО чтения данных список проверяемых гипотез H-1…H-n с
ожидаемым направлением эффекта (pre-registration). Всё, что найдётся в данных сверх списка,
маркируется «post-hoc» и требует подтверждения на holdout.

# 3. BRAINSTORM (`superpowers:brainstorming`, отдельная фаза)

Цель — расширить пространство гипотез, не backlog фич. Искать: неожиданные объяснения
наблюдаемого; пропущенные научные подходы; альтернативные определения BS; скрытые confounders
(тип звонка, тир контакта, длина истории, кто инициатор, время суток, role_fragile); признаки,
сильные на вид и пустые по сути; взаимодействия речь×поведение×история; longitudinal и
контекстные эффекты; неиспользованные подсистемы CallProfiler; ПАРАЛИНГВИСТИКУ (аудио есть —
паузы, латентность ответа, темп, вариативность F0, перебивания, смех), чего ни один прежний план
не трогал; сигналы, возникающие только на парах/триадах контактов (граф упоминаний);
асимметрию «что обещает владелец vs что обещают ему».
Результат `30-brainstorm.md`: каждая идея → гипотеза → как проверить → что её убьёт.

# 4. ЛИТЕРАТУРА (`deep-research`, multi-modal sweep, любые языки)

Приоритет: первичные исследования → peer-reviewed → systematic reviews → meta-analyses →
монографии → остальное. Направления (каждое — отдельный трек с собственным вопросом):
философия/определение BS (Frankfurt, Cohen, Pennycook «pseudo-profound», bullshit receptivity);
deception detection и его провалы (DePaulo et al. 2003 cues meta-analysis, Bond & DePaulo 2006
accuracy ~54%, Hartwig & Bond, Vrij; Levine truth-default; replication failures, effect sizes);
vagueness/hedging/evasion в дискурсе (Lakoff, Hyland, Bull & Mayer «equivocation», Clayman);
лингвистика обмана и её языковая зависимость (Newman/Pennebaker LIWC — и критика переноса на
русский); компьютерная лингвистика: fact-checking/claim detection, contradiction/NLI, stance,
hedge detection, speaker-level consistency; психометрика (construct/convergent/discriminant
validity, reliability, формативные vs рефлективные индикаторы — BS-index это что?); калибровка и
false confidence (Brier, reliability diagrams, decision-theoretic utility); HCI/cognitive load/
explainability для «одного взгляда» (Miller, Kahneman; alert fatigue; base-rate neglect);
longitudinal behavioral consistency и promise-keeping (trust research, reciprocity, reputation);
паралингвистика (Juslin & Scherer, pauses/latency и когнитивная нагрузка при обмане — и её
ненадёжность); русскоязычная прагматика телефонного разговора; ASR-robust NLP (шумоустойчивые
фичи, UNKNOWN-роли).
Для каждого вывода: доказано / хорошо поддерживается / вероятно / гипотеза / неизвестно +
effect size + boundary conditions + применимость к нашему корпусу. Искать И противоречащие
результаты, replication failures, publication bias. Результат — `10-literature.md`:
аннотированная библиография (≥60 источников, из них ≥20 первичных), таблица «сигнал →
доказанность → эффект → переносимость на RU-телефонию → что это значит для CallProfiler».
