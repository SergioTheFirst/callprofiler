# 20 — First principles: что измеримо, что нет, и как из этого выводится индекс уверенности

> Статус: round 2, 2026-08-22. Вывод от механизма, не от готовых формул. Каждое утверждение имеет
> id C-n в `claims-ledger.md`; здесь — цепочка рассуждения. Числа — в ledger с источником.

## 1. Цель и её декомпозиция

Цель (из промпта): владелец «одним взглядом значительно лучше понимает абонента И всегда знает,
насколько этому пониманию можно верить». Это ДВА разных объекта:

- **Характеристика абонента** — утверждение о человеке (пример: «обычно выполняет, что обещал»).
- **Уверенность системы** — вероятность, что характеристика верна, при имеющихся данных.

Смешивать их нельзя: «ненадёжный абонент» и «система плохо знает абонента» — разные состояния, с разным
действием владельца (первое — осторожность; второе — собрать данные/подтвердить). Текущий BS + перцентиль
смешивает их в один ранг (60-existing-bs-verdict.md).

## 2. Что наблюдаемо (данные), что нет (ментальные состояния)

Наблюдаемо на боксе: (a) текст реплик с ролями (роли хрупкие, `role_fragile`); (b) метаданные времени
(иммунны к ASR); (c) LLM-извлечения (шумные, с самооценкой); (d) обратная связь владельца (редкая,
смещённая к ярким случаям); (e) **исходы во времени** — обещание в звонке t, упоминание исполнения/провала
в звонке t+k.

Ненаблюдаемо: намерение обмануть, безразличие к истине (Франкфурт, L-001), знание истины говорящим,
источник ошибки (память/незнание/заблуждение). ⇒ **Любой индекс, определённый как «ложь/буллшит
абонента», нефальсифицируем на этих данных** (C-01): нет критерия, по которому его можно проверить.
Литература deception detection это подтверждает эмпирически: текстовые cues d≈0.10 (медиана 158 cues,
DePaulo 2003, L-008), люди 54% (Bond & DePaulo 2006, L-011), после коррекции на publication bias значимые
cues d≈0.15–0.19 (Luke 2019, L-016). Это не «нужна модель получше» — это отсутствие сигнала в канале.

Следствие (правило проектирования): **измеряем только то, для чего существует внешний критерий, который
система сама может собрать** (исход) или который владелец может подтвердить одним нажатием (✓/✗).

## 3. Конструкты: что отличимо в принципе

Таблица (§2 промпта). «Отличимо» = существует наблюдаемый критерий на этих данных.

| Явление | Критерий на данных | Вердикт |
|---|---|---|
| Невыполненное обязательство | исход в будущих звонках / ✓✗ владельца | **измеримо** (C-05) |
| Уверенность без основания | маркер уверенности при обещании × исход | **измеримо условно** (C-09): как разность P(провал\|уверенно) − P(провал\|хедж) |
| Повтор обещания без исполнения | det по датам (то же обещание ≥2 раз без kept) | измеримо, дёшево (C-05b) |
| Противоречие vs смена позиции | нет критерия без причинной модели диалога; честные расходятся часто (L-122: 98% reminiscence; L-120: лжецы не менее последовательны) | **не production**; эксперимент точности (C-02) |
| Ложь / буллшит / ошибка / незнание / заблуждение | ментальное состояние | **неотличимо** (C-01) |
| Гипербола / ирония / риторика / самопрезентация / манипуляция | нет RU-критерия при ASR (L-116 irony baseline слабый) | неотличимо |
| Ошибка памяти | нет | неотличимо |
| Уклончивость-вежливость | хеджи — норма RU-речи (L-108, L-115; V-4); сигнал — только относительный и в контексте прямого вопроса (L-024 Clayman, L-023 Bull & Mayer) | **эксперимент** (C-03) |
| ASR-артефакт как «противоречие» | verbatim-гейт + role_fragile + WER | частично отсекаем (C-07) |

Запрещённые подмены (неточность→BS, уверенность→ложь, противоречие→обман, эмоция→ненадёжность,
краткость→уклончивость) автоматически исключены: ни один из «подменных» входов не имеет критерия.

## 4. Новый главный конструкт: надёжность обязательств (CR)

**Определение.** CR(контакт) = вероятность того, что обязательство, которое этот контакт берёт на себя
перед владельцем, будет исполнено. Это не черта личности и не «доверие» — частота поведения в этой
диаде, с интервалом.

**Почему именно это.** (1) Единственный сигнал с внешним критерием, уже собираемый системой
(`promise_outcomes`, §8 data-surface). (2) Promise-keeping — поведенчески обоснованная основа доверия
(Mayer/Davis/Schoorman 1995 integrity, L-089; эксперименты Charness & Dufwenberg, Vanberg — L-090,
L-091: люди держат обещания по обязательству, не по выгоде → нарушение информативно). (3) Именно это
владелец может проверить одним нажатием («он сделал? да/нет»).

**Единица** — `contact_id` (диада), не graph-`entity` (BS был entity-level). Обещания живут в диаде;
досье — по контакту (dashboard.md); `entity_contact_map` — мягкая, не нужна для CR.

**Исходы.** `promise_outcomes.status ∈ {kept, late, broken, unknown}`. Первичная величина —
*исполнено* = kept ∪ late (позднее исполнение — всё же исполнение; «late» зависит от шумного парсинга
дат); вторичная — доля late среди исполненных («опаздывает»). `unknown` не входит в оценку, но **входит в
уверенность** (§6) и проверяется на смещение (E-2: исходы могут упоминаться неслучайно).

**Оценка.** Beta-binomial с эмпирически-байесовским приором (Jøsang & Ismail 2002, L-094; Efron & Morris
1975, L-129): приор Beta(α₀,β₀) подбирается по всем контактам юзера (метод моментов по долям
исполнения среди контактов с n≥5), затем для контакта

    α = α₀ + Σᵢ wᵢ·[исполненоᵢ],  β = β₀ + Σᵢ wᵢ·[провалᵢ],  wᵢ ∈ [0,1]

    wᵢ = w_label(методᵢ) · w_role(звонокᵢ) · w_time(возрастᵢ)

- `w_label`: owner-confirmed = 1.0; det-regex = q_det; llm = q_llm. **q_det/q_llm — НЕ константы, а
  измеренные точности** (E-1 adjudication); до измерения — консервативные 0.7/0.6 с пометкой
  `UNCALIBRATED` (plan R-07) — это честнее, чем 1.0, и проверяемо.
- `w_role`: 1 − UNKNOWN-доля звонка, где дано обещание (role_fragile — тот же механизм, непрерывный).
- `w_time`: 0.5^(возраст/h); h ∈ {∞, 365, 180} выбирается экспериментом E-8 по temporal-holdout
  log-loss (V-9 верно указывает: затухание — гипотеза, не факт; у нас оно параметр с тестом).

Точечная оценка — апостериорное среднее α/(α+β); интервал — 80% credible (квантили Beta). Шринкаж к
приору даёт корректное поведение при n→0 (оценка = популяционная база, широкий интервал).

**Коррекция шума ярлыков.** Если E-1 даёт sens/spec det-разрешителя, применяется Rogan–Gladen:
p = (p_obs − (1−spec)) / (sens − (1−spec)), clamp [0,1] (Carroll et al. 2006, L-138 — attenuation при
errors-in-variables). Реализуется как вторая формула-версия `cr-v1n`, включается только по исходу E-1.

## 5. Вторичные конструкты (условные)

- **Уверенность-без-основания (C-09):** для обещаний с маркером уверенности (det-regex: «точно»,
  «гарантирую», «сто процентов», «обязательно», «железно», «без вопросов») — Δ = P(провал|уверенно) −
  P(провал|без маркера). Показывать ТОЛЬКО если обе группы ≥5 исходов и 80%-интервал Δ не содержит 0
  (cluster bootstrap по звонкам, Cameron et al. 2008, L-130). Фраза: «уверенные обещания сбываются не
  чаще обычных». Включается по исходу E-5 (точность маркера ≥0.8).
- **Повтор без исполнения (C-05b):** одно и то же обещание (по word-overlap как в promise_outcomes)
  ≥2 раз без kept → строка в досье с цитатами и датами. Детерминировано, без LLM.
- **Противоречия (C-02), уклончивость (C-03):** остаются экспериментами E-6/E-7 с правилом решения;
  в production — никогда как число, только как класс E2-факт с цитатой после прохождения порога.

## 6. Индекс уверенности CI 1–100 — вывод

**Семантика (операциональная).** CI — калиброванная вероятность (в %) того, что показанная владельцу
характеристика контакта верна. «Верна» = истинное значение CR лежит в показанном диапазоне (band).
Критерий калибровки: среди контактов с CI≈X доля подтверждённых владельцем характеристик ≈X%.
CI=30: «скорее неизвестно» (показывать характеристику нельзя); 60: «вероятно, но проверь»; 90:
«почти наверняка». Это *уверенность системы в себе*, не свойство абонента.

**Вывод формулы (round 2).** Показываемая характеристика — апостериорная медиана m доли исполнения,
округлённая до фразы (§7). Уверенность в ней — по определению — апостериорная масса в окне ±0.1
вокруг m (окно сдвигается внутрь [0,1] у краёв):

    m  = median Beta(α, β)
    CI = 100 · ∫_{m−0.1}^{m+0.1} Beta(r; α, β) dr,   CI ∈ [1,100] после clamp

Семантика: «CI% — вероятность, что истинная доля исполнения в пределах ±10 п.п. от показанной».
Round 1 использовал фиксированные band — отвергнуто: band <0.4 шириной 0.4 давал негативный ярлык после
≈2 провалов, равные band 0.2 давали boundary-артефакт (истинная доля на границе никогда не получала
CI>56) — `box-package/scripts/00_ci_demo.py`, S-7. Это не постулат — единственная величина,
удовлетворяющая семантике «вероятность, что показанное верно» при байесовской модели §4. Все
требуемые входы §3 промпта входят **через α, β**, не через отдельные множители:
- объём evidence → n = Σw; давность → w_time; доля UNKNOWN/role_fragile → w_role; качество ярлыков →
  w_label; статус проверки владельцем → w=1 и исход заменяется подтверждённым.
- согласие независимых сигналов → при двух сигналах (det + LLM на одном обещании, согласны) w не
  удваивается (один исход = одно наблюдение); расхождение → исход = unknown.
- устойчивость во времени → косвенно: ICC по окнам — диагностика E-4, не вход (иначе два раза считаем
  одно и то же).
- длина истории / тип звонков / **число звонков — НЕ входят**: звонки без обязательств не дают
  evidence о CR. «Много звонков ≠ понимание» выполняется конструктивно.

**Свойства (тесты офлайн, R-tests):** монотонность по n при фиксированной доле (больше согласных
исходов → CI↑); границы (n=0 → CI = масса приора в band, т.е. низкая; n→∞ с чистой долей → 100);
детерминизм (чистая функция от хранимых счётчиков + версии); инвариантность к порядку исходов;
убывание при росте UNKNOWN-доли; синт-калибровка (на synth с известной истиной ECE ≤ 0.05 — проверка
механизма, «synth, не evidence»).

**Фразы (от медианы m).** ≥0.8 «держит слово», [0.6,0.8) «в основном держит», [0.4,0.6) «через
раз», [0.2,0.4) «чаще не выполняет», <0.2 «почти не выполняет». Негативные фразы (<0.4) — только при
n_eff ≥ 4 (цена ложного негатива; C-20). Фразы `promise_outcomes` (0.8/0.5) заменяются этими (R-09).
Идеализированные пороги (равномерный приор, q=1): CI≥60 при ≈4 чистых исходах, ≈7 при доле 0.9, ≈16
при 0.5 (C-11); реальные — выше (шум ярлыков, E-3).

**Цензура (C-19, S-8).** `unknown`-исходы не входят в α/β, но: *покрытие* = разрешённые/все обещания
контакта; покрытие < 0.3 ⇒ CI cap 59 («похоже») до результата E-2; при MNAR (E-2 исход B) —
`unknown` с прошедшим сроком и ≥2 последующими звонками входят с весом w·P(провал|unknown) по измеренной
доле (`cr-v1c`). Повторное обещание без исполнения (C-05b) — качественная строка с затуханием 6 мес.

**Калибровка на боксе — две стадии (E-3; C-10 R2).** Стадия 1: adjudication ≤40 элементов
(стратификация по n/методу/статусу, рандомизированный порядок, adjudicator слеп к CI и методу) →
reliability diagram + Brier + ECE_adapt (адаптивные бины, bootstrap по контактам; L-074) — отчёт
*предварительный*, число CI в UI не включается. Стадия 2: ✓/✗-петля в досье/боте накапливает
подтверждённые исходы; когда ≥150 adjudicated по ≥30 контактам и ECE_adapt ≤ 0.15 (верх 80%-CI ≤ 0.20)
→ `numeric_ci_enabled=1`; иначе один параметр temperature на logit(CI) (подбор на половине, проверка
на другой); повторный провал → число остаётся выключенным, только словесный тир evidence.

**Уровни.** Два: (i) per-claim evidence class (T-15/T-23): E0 подтверждено владельцем; E1 поведенческий
исход с verbatim-цитатой; E2 LLM-извлечение с verbatim-проверкой; E3 непроверенное (LEGACY_UNVERIFIED,
не показывается как факт). (ii) per-contact CI — только для ГОЛОВНОЙ характеристики (CR band).
Правило агрегации: CI контакта = CI головной характеристики; прочие утверждения несут свой класс,
а не число. (Не усредняем: среднее по разнородным утверждениям не имеет вероятностной семантики.)

**Отношение к существующему (R2).** `admiralty` (буква A–F + цифра info из среднего LLM-confidence)
**удаляется целиком** — C-18 retracted (S-6): буква без легенды — ложная точность, цифра — самооценка
модели. `age confidence 1–100` — остаётся отдельным объектом с тем же контрактом семантики
(«калиброванный %») и тем же скриптом проверки калибровки (R-24); унификация числа — нет (разные
утверждения). `insufficient_evidence` T-15/T-23 — CI<50 ⇔ `insufficient_evidence` для головной
характеристики. `psychology_profiler` паттерны `promise_breaker/reliable` → CR-фраза; четыре trait-паттерна
на мёртвых входах удаляются (C-17).

## 7. Поведение UI при низкой уверенности

HCI-вердикт (V-7): точные числа читаются как уверенность (Jerez-Fernandez, L-084); объяснения
усиливают over-reliance (Bansal, L-083; Buçinca); лекарство — интервалы и cognitive forcing, не тишина.
Правила (R2, C-20):
- **Факты — всегда** (класс E0/E1): строки «обещал X (дата) → исполнено / не исполнено / неизвестно»
  с цитатой; ✓/✗ на каждой. Факты — не характеристика; это cognitive forcing без ярлыка.
- **Характеристика (фраза CR)** — при CI ≥ 50; при 50 ≤ CI < 60 — со словом «похоже».
- **Число CI** — только при `numeric_ci_enabled=1` (стадия 2 калибровки); до того вместо числа —
  словесный тир evidence: `no_data` / `insufficient` / `limited` / `moderate` / `substantial`
  (по n_eff: 0 / <2 / <4 / <8 / ≥8 — пороги пере-привязываются к E-3).
- CI < 50 (или тир < `limited`): **характеристика не показывается**; «надёжность: данных мало» +
  факты + ✓/✗ (путь поднятия уверенности — подтверждённый исход весит 1.0).
- Негативные фразы — дополнительно n_eff ≥ 4; покрытие < 0.3 — не выше «похоже».
- Никогда: «ненадёжен»/«врёт»/«BS»/буква A–F; только «чаще не выполняет обещанное» + цитаты.
- Карточка 512 байт: строка `надёжность: {фраза} · {тир|ув. N}` или `надёжность: данных мало`.
- Digest/≤300 симв.: суффикс фразы только при CI≥50; «недавнее vs общее» — только при ≥3 исходах за
  6 месяцев и расхождении фраз (graft из design panel).
- Data-quality строка в досье (graft): «роли в части звонков неясны» при средней UNKNOWN-доле
  обещаний > 0.3; «исходы известны по малой части обещаний» при покрытии < 0.3.

## 8. Где считается, детерминизм, версии

- `promise_outcomes` (уже DERIVED, rebuild) → новая DERIVED таблица `contact_reliability` (posterior,
  band, CI, n_eff, version, params_hash) — чистая функция от `promise_outcomes` ⋈ `calls.role_fragile`
  ⋈ `fact_feedback` + `reliability_params(user_id, version, alpha0, beta0, q_det, q_llm, half_life)`.
- Пересчёт: CLI `reliability-build --user X` (det, без LLM) — вызывается в конце `promise-outcomes`, в
  watcher-автофите после `recompute_tiers`, и в `graph-replay` НЕ вызывается (граф не вход). Инвариант
  `graph.md` не затрагивается: `events`/`entity_metrics` не меняются; BS v1 замораживается (R-02), не
  переопределяется.
- GPU: только numpy/SQL → совместимо с ASR-окном; LLM-донасыщение исходов остаётся `--llm` в LLM-окне.
- Версии: `CR_VERSION='cr-v1'` (+`cr-v1n` с noise-correction), `reliability_params.version`; смена
  формулы = новая версия + полный rebuild (как `TABLE_VERSION` у age_style).

## 9. Неочевидные следствия (анти-шаблон, §4 промпта)

1. **Большинство контактов получат «данных мало».** Это не провал, а главный результат честности:
   для них система раньше показывала ранговый ярлык. Сюрприз-ledger S-1.
2. **Число звонков не поднимает уверенность вообще** — даже 500 звонков без обязательств дают CI приора.
3. **Владелец может поднять CI одним ✓** — подтверждённый исход весит 1.0 против ~0.7 у det: путь
   «adjudication → уверенность» короче, чем «больше данных».
4. **Старый BS не чинится, а замораживается**: оживление мёртвых членов без валидности — худшее из
   решений (ложная точность вместо нуля).
5. **Граф (entities/events) остаётся для фактов/связей, но перестаёт быть источником «надёжности»** —
   CR живёт в контактном пространстве, где есть исходы.
