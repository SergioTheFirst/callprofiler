# 60 — Вердикт по текущему BS-index (`v1_linear`) и смежным «оценкам надёжности»

> Статус: round 1, 2026-08-22. Основание — `40-data-surface.md` (код), claims C-01…C-06
> (`claims-ledger.md`). Вердикт НЕ про «плохая формула» — про то, что именно измеряется, кем и с
> какой проверкой.

## Вердикт в одну строку

`entity_metrics.bs_index` сегодня = `20 · min(contradictions/total_calls, 1)`, где `contradictions` —
число LLM-помеченных «противоречий» (без определения, без атрибуции говорящего, без проверки
дословности в боевом пути), деленное на число звонков с хоть каким-то событием; затем ранжируется
так, что 10% сущностей всегда «critical». **Это не измерение надёжности абонента — это ранг
частоты одного неопределённого LLM-ярлыка.** Остальные четыре члена формулы мертвы (D1).

## Что именно не так — по уровням

### Уровень 0 — конструкт (что измеряем)
- «BS» в промпте определён как шкала `0=честный конкретный … 100=сплошной пиздёж и уклонения`
  (`analyze_v001.txt:68`). Склеены: ложь (знание истины + намерение), bullshit по Франкфурту
  (безразличие к истине), уклончивость (прагматика, часто вежливость), неконкретность (стиль/жанр).
  Литература (C-01, C-03) говорит, что эти вещи из текста в принципе НЕ разделяются надёжно; промпт
  требует от 9B-модели сделать это одним числом. ⇒ `bs_score`/`bs_evidence` — мнение модели о
  неопределённом конструкте, не сигнал.
- `structured_facts.fact_type` — шесть ярлыков без определений (D4). Модель свободна называть
  «vagueness» любой хедж, а «contradiction» — любое изменение позиции, включая рациональное
  обновление после новой информации (C-02).

### Уровень 1 — извлечение (LLM → events)
- Нет `who` (D2): промпт не просит, INSERT пишет `'UNKNOWN'`. Любой счётчик «уклончивости» —
  смесь двух говорящих; при подмене ролей (диаризация хрупкая, `role_fragile`) — ещё и смесь с
  владельцем.
- Дословность цитат в боевом пути не проверяется (D3) — `MIN_MATCH_RATIO=0.72` и `SequenceMatcher`
  работают только при replay. До первого `graph-replay` граф содержит непроверенные цитаты; после —
  та часть, что прошла 0.72 (а 0.72 по `difflib` — это уже «похоже», не «дословно»).
- LLM-`confidence` с гейтом 0.6 — самооценка модели (C-06: verbalized confidence у малых моделей
  overconfident и слабо калибрована); гейт выкидывает «неуверенные» факты, не проверяя верные.
- Клип входа (D9) делает внутризвонковое «противоречие» невидимым для длинных звонков — ровно там,
  где оно было бы информативно.

### Уровень 2 — агрегация (events → entity_metrics)
- Мёртвые члены (D1): формула с весами 0.40/0.20/0.15/0.15/0.10 НИКОГДА не получала ненулевых
  `broken`, `vagueness`, `blame_shift`, `emotion_spike` из боевого пути. Тесты проверяют формулу на
  рукописных входах (D11). Это тот же класс, что «зелёные тесты ≠ доказательство»
  (decisions.md 2026-06-06, 2026-08-21).
- Без окна давности (D7) — накопленный за годы счётчик; `total_calls` зависит от того, сколько
  звонков породили хоть одно событие, а не от объёма общения.
- Веса априорные; индекс формативный (C-04) — его валидность можно установить ТОЛЬКО внешним
  критерием, которого в системе нет, кроме `promise_outcomes` (§8 data-surface) и
  `fact_feedback`.

### Уровень 3 — калибровка/ярлык
- Перцентильная «калибровка» (D6) — не калибровка, а ранжирование: независимо от данных четверть
  «reliable», десятая часть «critical». При массе нулей (следствие D1) пороги p25=p50=0 →
  «noisy» начинается с bs=0+ε. Сам термин «calibrated thresholds» в `graph-health` вводит в
  заблуждение: проверяется наличие строки, не качество.
- `admiralty.source_grade` наследует ранг: A/B — «reliable» по рангу, потом уточнение по
  `kept_ratio` (единственный поведенческий вход). E = «ненадёжен» — для 10–25% сущностей по
  построению.

### Уровень 4 — презентация
- Карточка показывает `grade: B3 — обычно надёжен, информация возможно верна` — две буквы/цифры,
  где «3» = среднее LLM-confidence (самооценка), «B» = ранг. Формулировка читается как суждение о
  человеке (CONSTITUTION: не trust score), источник невидим.
- Паттерн `reliable` при `broken==0 ∧ promises≥3` (D8) — при `broken≡0` ставится всем с ≥3
  обещаниями → системный ложный «надёжный».
- Два BS (D5): `avg_bs_score` (LLM, half-life 90d) кормит `advice`; `bs_index` кормит grade/досье;
  они могут противоречить друг другу на одном контакте — и нигде не сверяются.

## Что СПОСОБНА отличить система сегодня (честный ответ на вопрос §2 промпта)

| Явление | Отличимо из текста+ASR? | Сегодня в системе |
|---|---|---|
| Сдержанное/несдержанное обещание (поведенческий исход) | ДА, частично (det-regex 120 дней; LLM-донасыщение) | `promise_outcomes` — единственный внешний критерий |
| Повтор одного и того же обещания без исполнения | ДА (det по датам) | нет |
| Противоречие vs смена позиции после новой информации | НЕТ без диалоговой причинной модели; C-02 | LLM-ярлык без определения |
| Ложь | НЕТ (C-01, C-03): cues d<0.2, люди 54% | `bs_score` — претензия на это |
| Bullshit (безразличие к истине) | НЕТ из текста; только по поведению во времени (невыполнение + несогласованность) | нет |
| Ошибка / незнание / добросовестное заблуждение | НЕТ | — |
| Уверенность без основания | частично: «точно/гарантирую» + последующий провал | нет (есть сырьё) |
| Гипербола / ирония / риторика | НЕТ (RU-ирония, ASR) | — |
| Самопрезентация / манипуляция | НЕТ | — |
| Ошибка памяти | НЕТ | — |
| Уклончивость-вежливость | НЕТ без жанровой нормы (C-03: хеджи — норма RU-речи) | hedge-лексикон 12 слов без нормы |
| ASR-артефакт как «противоречие» | частично: verbatim-гейт + role_fragile | только в replay |

Запрещённые подмены (неточность→BS, уверенность→ложь, противоречие→обман, эмоция→ненадёжность,
краткость→уклончивость) — в текущей формуле присутствуют ВСЕ ПЯТЬ по замыслу (vagueness, emotion_spike,
contradiction — как вклад в «BS»); спасает лишь то, что четыре из них мертвы.

## Решение (предварительное, уточняется в 70-synthesis)

1. `v1_linear` **не чинить** (нет смысла оживлять мёртвые члены, чья валидность не установлена) —
   заморозить как `LEGACY_UNVERIFIED`, сохранить колонки/версию для аудита, перестать показывать как
   «reliability».
2. Новый слой строится вокруг единственного сигнала с внешним критерием — **поведенческих исходов
   обещаний** — плюс явная **оценка уверенности системы**, которая честно говорит «данных мало»
   для большинства контактов.
3. Лингвистические сигналы (хеджи, специфичность, «противоречия») — только как **кандидаты в
   эксперимент на боксе** с заранее записанным правилом решения; в production — не раньше, чем
   покажут прирост над поведенческим базисом на holdout.
4. `bs_score`/`bs_evidence` из промпта — изъять из агрегации (оставить в raw_response как legacy);
   `advice` перевести на новые входы.

Подробная трассировка решение → задача → тест — в `90-execution-plan.md`.
