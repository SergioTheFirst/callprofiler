# Правила решения (записаны ДО данных; менять только новым коммитом с обоснованием в `99-rounds.md`)

Обозначения: CI₈₀ — 80% cluster-bootstrap интервал; «исключает 0» — весь интервал по одну сторону.
Все пороги относятся к confirmation-подмножеству C (`protocol.md` §2), если оно есть.

## E-0a (script 01/02/03) — baseline
- D1 подтверждён ⇔ `MAX(bs_index) ≤ 20` ∧ все `vagueness_count/blame_shift_count/emotional_spikes/
  broken_promises = 0`. Иначе — **стоп**: пересмотреть `40-data-surface.md` §4 до R-02.
- Доля контактов с ≥4 разрешёнными исходами = `p4`. `p4 < 0.1` → в UI по умолчанию раскрывать блок
  «данных мало» с ✓/✗ (R-10 вариант «фокус на петле»); иначе стандартный.
- Средняя UNKNOWN-доля звонков с обещаниями > 0.3 → E-9 пропускается, `role_weight_mode=continuous`.

## E-1 (R-16) — точность исходов
- `q_det ≥ 0.80` → `cr-v1`, `q_det := измеренное`, `calibrated=1`.
- `0.6 ≤ q_det < 0.80` → R-17 (`cr-v1n`), если нижняя граница CI₈₀ `sens−(1−spec)` ≥ 0.25; иначе `cr-v1` с `q_det := измеренное` (граница 0.70–0.80 намеренно консервативна — мощность E-1).
- Round 3 (S2/S4/S5): отчёты E-1/E-2/E-3(1) обязаны содержать записанную мощность/ширину CI и ×1.3-расширение ECE-интервала при микро-кластерах; решения на границе — всегда консервативная ветка.
- `q_det < 0.6` → `w_label(det) := 0.3`; фразы только по E0+llm; R-19 откладывается до повторного E-1
  после улучшения det (отдельная задача вне плана).
- Аналогично `q_llm` (если llm-исходов ≥ 8 в выборке; иначе `q_llm` остаётся 0.6, `UNCALIBRATED`).
- E-1b: если при `q ± 0.05` фразу меняют > 20% контактов с `show_phrase=1` → `tier_cuts` сдвигаются на
  шаг вверх (insufficient<3, limited<6, moderate<12).
- Роль перепутана в ≥ 5% → `role_weight_mode=continuous` фиксируется, E-9 пропускается.
- FP извлечения («это не было обещание») > 0.3 → риск R-9: стадия 2 (R-20) не начинается до задачи
  по извлечению обещаний.

## E-2 (R-18) — цензура
- n adjudicated overdue-unknown < 8 → решение отложено; cap покрытия 0.3 остаётся.
- `|π_b − π_r| ≤ 0.10` → MAR; `coverage_cap := 0` (cap снимается).
- `> 0.10` → `cr-v1c`, `pi_unknown_broken := π_b`; cap остаётся.

## E-3 стадия 1 (R-19)
- Отчёт предварительный. `numeric_ci_enabled` остаётся 0 при любом исходе.
- Верх CI₈₀ ECE_adapt > 0.25 ∧ направление overconfidence → `tier_cuts` на шаг вверх; underconfidence →
  без изменений (консервативно).

## E-3 стадия 2 (R-20)
- Условие входа: ≥150 `outcome_feedback` по ≥30 контактам.
- ECE_adapt ≤ 0.15 ∧ верх CI₈₀ ≤ 0.20 (по C-половине, verdicts fit-а не участвуют) → `numeric_ci_enabled=1`.
- Иначе: temperature `T` на logit(CI) — только при ≥250 verdicts — подбирается на E, проверяется на C: ECE_C ≤ 0.15 → включить с `T`;
  иначе число остаётся выключенным (задокументировать, пересмотр через 3 месяца).
- < 20 verdicts за 8 недель → R-7: упростить петлю (R-20 UI-правка), порог не снижать.

## E-8 (R-21) — затухание
- h — фиксированная сетка {∞,365,180}, приор и веса только по исходам < T₀ (без утечки). Дефолт `h=∞`. Заменяется на h ∈ {365, 180}, только если CI₈₀(log-loss(h) − log-loss(∞)) < 0 целиком
  (Holm на 2 сравнения). Если по тирам (core/active vs остальные) знаки разные и оба CI исключают 0 →
  h по тирам; иначе единый.

## E-4 (R-22) — предсказательная ценность
- CI₈₀ lift log-loss (base − CR) > 0 → `phrase_mode=predictive`; иначе `descriptive`.

## E-9 (R-23)
- Пропускается при условиях E-0a/E-1 выше. Иначе: |Brier(continuous) − Brier(off)| < 0.005 → `off`;
  иначе режим с меньшим Brier. Harm-gate: контакт, у которого все звонки с обещаниями `role_fragile=1`, всегда `continuous`.
