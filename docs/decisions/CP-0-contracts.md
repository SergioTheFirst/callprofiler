## C-01 — Основной ASR: **GigaAM primary, Whisper fallback**

- **Решение:** канонический контракт — `asr_backend: gigaam` (`GigaAM-v3-RNNT`, локальная HF-модель)
  как основной путь; `faster-whisper large-v3` остаётся поддерживаемым fallback, выбираемым
  `asr_backend: whisper`.
- **Почему так:** это уже фактическое состояние кода (`transcribe/asr_runner.py` Protocol +
  фабрика), `configs/base.yaml` и `AGENTS.md` (после `6361c6c`). Против — только текст
  `CONSTITUTION.md` (статьи 3/5/9). Выбор в пользу кода: обратный вариант потребовал бы
  переписать рабочий ASR-путь ради согласования с документом, чего никто не измерял и не просил.
- **Совместимость:** оба backend'а обязаны удовлетворять единому `TranscriptionResult`-контракту
  из T-11. Смена ASR-модели в будущем — только через R-01.
- **Что правится:** `CONSTITUTION.md` статьи 3/5/9 и таблица решений — отдельным owner-approved
  коммитом. Код не трогаем.
- **Дата ревью:** при первом изменении `asr_backend` или по результатам R-01.

## C-02 — Размер caller card: **512 UTF-8 байт**

- **Решение:** канон — **512 байт в UTF-8**, а не 500 символов.
- **Почему так:** ограничение физическое, а не редакторское: файл читает MacroDroid на Android,
  и бюджет измеряется байтами. `MAX_CARD_BYTES = 512` уже в `card_generator.py` и в тестах;
  «500 символов» в Конституции — величина, которую невозможно проверить на стороне потребителя.
- **Следствие для T-19:** обязательные строки (идентификация / risk / freshness-штамп) никогда не
  режутся; опциональные выбрасываются целиком по приоритету; обрезка внутри свободного текста
  допускается только с сохранением валидности UTF-8. Половина строки — дефект.
- **Что правится:** `CONSTITUTION.md` стр. 210 — отдельным owner-approved коммитом.

## C-03 — pyannote: **решено ранее владельцем, здесь только фиксируется**

- **Модель:** `pyannote/speaker-diarization-3.1` — решение владельца 2026-08-07
  («оставить 3.1, ничего не менять», `CHANGELOG.md`). **Не переоткрывать.**
- **Runtime:** фактически `pyannote-audio 4.0.4` + torch 2.6.0+cu124; runner уже на API 4.x.
- **Способ загрузки:** `use_auth_token=` с fallback на `token=` (`_load_pretrained`), аудио —
  только in-memory `{waveform, sample_rate}` (обход torchcodec на Windows), телеметрия выключена
  (`OTEL_SDK_DISABLED` + `set_telemetry_metrics(False)`), вывод распаковывается через
  `_extract_annotation` (`DiarizeOutput` в 4.x).
- **Offline:** артефакт модели загружается только из локального allowlisted каталога, без сетевого
  download в production (реализует T-11).
- **План Б владельца:** чистый ECAPA-TDNN вместо `pyannote/embedding`; переоткрытие модельного
  вопроса — только при DER > 15% на собственном корпусе.
- **Что правится:** `CONSTITUTION.md` стр. 305-306 и `AGENTS.md` (дерево модулей + таблица
  решений) — «3.3.2 / только use_auth_token» устарело.

## C-04 — Telegram: **opt-in transport с явным whitelist полей**

- **Решение:** Telegram — **опциональный** транспорт, выключаемый целиком; «100% локально»
  относится к обработке (аудио, ASR, диаризация, LLM), а не к добровольной доставке уведомлений.
- **Разрешено отправлять:** имя/роль контакта, risk-индикатор, короткая сводка звонка, строки
  обязательств и напоминаний, служебные отчёты doctor/daily.
- **Запрещено по умолчанию:** сырой транскрипт, аудиофайл, полный prompt, цитаты-улики
  (`evidence`/`quote`) и любые PII-поля (телефон в полном виде, реквизиты). Расширение списка —
  отдельное решение владельца, не молчаливое.
- **Механика:** классификация privacy-level задаётся на уровне `outbox`-записи (T-17); payload,
  не прошедший whitelist, не отправляется, а попадает в operator view.
- **Логи:** токен и содержимое сообщений не логируются даже фрагментами (T-21).

## C-05 — Branch/release policy: **прямой push в `main`**

- **Решение:** единственная политика — работа и push напрямую в `main`, без feature-веток.
- **Почему так:** это действующее постоянное разрешение владельца (`CLAUDE.md`: «Push to main only.
  No feature branches»; `CONTINUITY.md`: git-автономия с 2026-06-04) и фактическое поведение —
  собственные коммиты владельца идут в `main`. Требование `AGENTS.md` работать на ветке
  `claude/clone-callprofiler-repo-hL5dQ` — реликт разового клон-задания и противоречит обоим.
- **Компенсация отсутствия PR-гейта:** каждая задача backlog заходит отдельным коммитом с зелёным
  targeted suite; релизный переход (CP-5) требует явного go/no-go владельца; `git push --force`
  запрещён.
- **Что правится:** `AGENTS.md` строки 128 и 183-184 — отдельным коммитом.
- **Дата ревью:** при появлении второго разработчика политика пересматривается немедленно.
